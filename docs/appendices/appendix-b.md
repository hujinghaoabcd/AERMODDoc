# 附录 B　错误消息代码说明

在开始浓度或沉降计算前，AERMOD 会检查控制文件结构、语法、关键字、参数、必需输入和选项冲突，并尽量避免除零等运行时错误。

## 消息输出位置

1. **主输出文件消息汇总：** 始终生成，统计各类消息并列出致命错误和警告；
2. **详细消息文件：** 使用 `ERRORFIL` 时生成，包含全部消息及产生顺序。

```text
CO STARTING
   ERRORFIL errormsg.out
CO FINISHED
```

主输出中通常有两处汇总：设置阶段之后一处，文件末尾一处。第二处汇总整个模型运行，包括设置和计算阶段。

## 消息类型

| 类型 | 代码 | 含义 |
|---|---|---|
| Fatal Error | `E` | 阻止后续有效处理；设置阶段仍可能继续读入以发现更多错误 |
| Warning | `W` | 不停止模型，但提示可疑输入或可能影响解释的条件 |
| Information | `I` | 对用户有参考价值，但不直接影响结果有效性 |

## 消息布局

```text
RE W220 39 REPOLR: Missing Origin ... GRIDPOLR POL1
│  │    │  │       └─ 详细说明和提示字段
│  │    │  └─ 生成消息的子程序
│  │    └─ 输入文件行号
│  └─ 类型与三位消息编号
└─ 功能路径 ID
```

若错误位于 `INCLUDED` 外部文件中，行号和提示字段会用于区分主控制文件与外部文件。遗漏输入常在路径结束检查时才被发现，因此消息行号可能指向 `FINISHED` 附近，而不是实际应插入记录的位置。

调试时应先处理最早出现的致命错误；一个基础错误可能引发多条后续衍生消息。
