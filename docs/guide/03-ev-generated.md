# 3.6 EV 事件路径：AERMOD 自动生成的事件

> 对应 EPA 2023 版 AERMOD 用户指南第 3.6 节完整中文译文。路径标识、关键字、参数名、事件名、源组 ID 和控制文件示例保留英文；法规应用应以 EPA 英文原文及当前模型版本为准。

<a id="ev-3-6-1"></a>
## 3.6.1 使用 AERMOD 模型生成的事件

AERMOD 提供 `CO EVENTFIL` 选项，用于生成可供后续 `EVENT` 处理直接使用的输入文件，详见第 3.2.14 节。

启用该选项时，模型会：

1. 将原 AERMOD 控制文件中的相关输入复制到事件处理输入文件；
2. 根据本次常规模型运行的结果生成 `EV` 路径输入；
3. 按 `EVENTPER` 和 `EVENTLOC` 的规定语法写入事件信息。

自动生成的事件包括：

- 由 `OU RECTABLE` 识别的设计浓度，例如第一高值、第二高值和其他指定排序值；
- 由 `OU MAXIFILE` 识别的阈值超限事件。

AERMOD 自动生成的事件位置始终采用笛卡尔坐标。

### 自动事件名称

为了便于识别并管理模型生成的事件，AERMOD 对 `Evname` 采用固定命名规则。

```text
H1H01001
```

表示：

- 第一高值；
- 1 小时平均；
- 第 1 个污染源组。

```text
H2H24003
```

表示：

- 第二高值；
- 24 小时平均；
- 第 3 个污染源组。

```text
TH030010
```

表示第 10 个 3 小时平均阈值超限事件。

```text
TH240019
```

表示第 19 个 24 小时平均阈值超限事件。

### 自动生成文件中的排列

在 AERMOD 生成的事件处理输入文件中：

1. 设计浓度事件首先列出；
2. 阈值超限事件随后列出；
3. 阈值超限事件按平均时间分组。

为便于用户审查自动生成的文件，并判断哪些事件值得重点分析，AERMOD 会把事件对应的实际浓度值作为 `EVENTPER` 记录的最后一个字段写入。

该附加浓度值仅用于提供信息，AERMOD 在事件处理计算中会忽略该字段。

### 重复事件

根据所选输出选项和模型结果，同一时空事件可能同时作为：

- 一个设计值事件；
- 一个阈值超限事件。

因此，同一事件可能在自动生成的输入文件中出现不止一次。

### 输入顺序与输出顺序

AERMOD 按日期顺序处理事件，并在每个事件完成后立即输出结果。因此，输出文件中的事件顺序通常不会与输入文件中的顺序完全一致。

只有当所有事件均由 `MAXIFILE` 生成时，输出顺序通常才与输入顺序一致。
